> **状态**：报告（2026-10-21 调研，含 10-19 抓包核对）

## 4. 我们能赢的地方

| 维度 | 图像识别 | 我们（协议） |
|---|---|---|
| 速度 | 一次摸头要截图+识别+点击，秒级 | 一次请求 100ms 级 |

## 5. 现在就能补的（协议已就绪，按性价比排序）

### 纯领奖，零风险

1. **邮箱一键领取** — `mail/check(7001)` 探未读 → `mail/list(7000, IsReadMail=false)` → `mail/receive(7002, MailServerIds)`。
   收益：活动奖励、月卡、补偿；不领会过期。
2. **任务奖励批量领取** — `mission/list(8000)` 看 `ProgressDBs` → `mission/multiplereward(8002, MissionCategory)`。
   每日 5 任务 = 300 青辉石 + 材料；`MissionCategory`：1 = 日常（1509 样本 `Category=1`），周常/成就待试。
3. **PASS 奖励** — `battlepass/check(51006)`（`HasCompleteMission`/`HasNotReceiveReward` 天然探针）→
   `missionmultiplereward(51005)` 任务奖励、`receivereward(51002)` 等级奖励。
4. **每月签到（出勤奖励）** — `attendance/reward(9002)`，参数 `AttendanceBookUniqueId / Day / DayByBookUniqueId`，
   签到簿数据从 loginsync 取。

### 有业务逻辑，收益高

5. **战术对抗赛自动战斗** — `enterlobby(22000)` 拿对手与券数 → `enterbattle(22004)` **直接返回战果**
   （服务端演算，无独立结算接口；`IsServerRunBattle` 即「跳过对战过程」设置），券尽即停。
6. **商店购买** — `shop/list(10002, CategoryList)` 拿 `ShopInfos`（`ShopUniqueId/GoodsId/价格/限次`）→
   `shop/buymerchandise(10000, ShopUniqueId, GoodsId, PurchaseCount)`。可按白名单买 AP 药、战术教育 BD、碎片。
7. **总力战扫荡 + 赛季奖励** — `raid/lobby(17014)` → `raid/sweep(17019, UniqueId, SweepCount)` → `raid/seasonreward(17013)`。
   **sweep 不需要战斗协议**，前提是本季已有通关记录。
8. **自动制造** — `craft/list(21000)` → `selectnode(21001)` → `updatenodelevel(21002)` → `beginprocess(21003)` → `reward(21005)`；
   「三解」走 `shiftingbeginprocess(21007)`。难点是节点优先级策略。

## 6. 还缺什么：按优先级排列的抓包清单

> ⚠️ **大决战、综合战术测试、总力战都是周期性开放活动**（不是常驻副本）。
> 只有活动窗口内才能抓包与实测：非开放期这些接口返回"未开放"，
> 所以这三块只能等窗口期再做，不能提前实现或验证。


| 优先级 | 缺的东西 | 现在有什么 | 抓包时要做什么 |
|---|---|---|---|
| **P0** | **大决战（EliminateRaid）** | 只有 `lobby(45001)` | 赛季开放时：进大决战 → 打一场 → 扫荡一次 → 领赛季奖励。需要 enter/end battle、sweep、seasonreward、ranking 一整套（协议号应落在 4500x 段）。 |
| **P1** | **综合战术测试（演习）** | 无 | 开放期间进一次 → 打一场 → 领奖。 |
| **P1** | **联合行动（MultiFloorRaid）** | 无（loginsync 里有 `MultiFloorRaidSyncResponse`） | 进大厅 → 打一层 → 结算。 |
| **P2** | **MomoTalk** | 无（loginsync 里有 `MomoTalkOutLineResponse`） | 打开 MomoTalk → 进一个未读对话 → 读完/选一个回复。 |
| **P2** | **好友增删** | 只有 `friend/check` | 加一个好友、删一个好友（BAAS 的「清理好友」需要）。 |
| **P3** | 日常小游戏 | 只有 `missionlist(35003)` | 小游戏开放时玩一局。 |
| — | 剧情关（活动） | **已有** 30000/30036/30037/30027/19003 | 不用抓，只差实现 |

**不用抓、只需实测的**：每日特别委托走哪个 `contentsweep` 的 `Content` 枚举（现有 3=悬赏、8=交流会），以及活动扫荡的 `EventContentId` 参数。

## 7. 比功能更值得抄的：调度层

BAAS 每个任务有四个维度：`daily_reset`（每日几点跑）、`interval`（轮询间隔）、`priority`（顺序）、`pre_task/post_task`（依赖）。

我们目前只有「一键清（拖拽顺序）+ 咖啡厅 10 分钟轮询」，缺：

- **按时间点触发**：领奖类卡 4:00 刷新后；咖啡厅卡 4:00/16:00；竞技场卡 20:00 结算前。
- **任务依赖**：先扫荡再领任务奖励（否则任务没完成白跑一轮）。
- **失败不阻塞**：单模块失败不应中断后续（现在串行、报错即停）。
- **通知**：可选 webhook（注意别把 token/UID 发出去）。

## 8. 建议的落地顺序

1. **P0 三件套**：邮箱 → 任务奖励 → PASS（都复用 `call_session`，一个下午能完，收益立刻可见）
2. **商店购买**：接口已就绪，按白名单买 AP 药/碎片
3. **总力战扫荡**：赛季期收益最大
4. **制造**：常驻收益，需先定节点优先级
5. **补抓包**：竞技场结算 → 大决战（这两项一补，日常就只剩推图没覆盖）

> 不建议追：推图、好友清理、小游戏——协议成本高、自动化收益低，图像方案能做只是因为点屏幕不要钱。
