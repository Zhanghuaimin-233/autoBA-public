# 邮箱 / 任务奖励 / 商店（2026-10-21 接入）

## 1. 邮箱

```
mail/check(7001)                          → {Count} 未读数
mail/list(7000, IsReadMail=false, ...)    → {MailDBs[], Count}
mail/receive(7002, MailServerIds[])       → ParcelResultDB
```

- `list` 的请求参数照抄客户端：`IsDescending=true, IsReadMail=false, PivotIndex=0, PivotTime="9999-12-31T23:59:59", mailSortingRule=0`
- 实测（2026-10-21）：3 封 → **行动点 ×60、战术奖币 ×3**，一次请求全领
- 待补：`MailDBs[].Title` 取出来是空串，标题字段名还没定位（当前 UI 不显示标题）

## 2. 任务奖励

```
mission/list(8000, EventContentId=null)          → ProgressDBs[] / MissionHistoryUniqueIds[]
mission/multiplereward(8002, MissionCategory)    → ParcelResultDB
```

- `MissionCategory`：**1 = 日常**、2 = 周常、3 = 成就（1502 等日常在样本里 Category=1；2305 周常在 8002 报错样本里为 2）
- 实测：Category 1 一次领到 **行动点 ×100、中级活动报告书 ×3、Type3:2 ×2**
- **`ProgressDBs[].Complete == true` 不等于可领**：领完之后仍有一批 Complete 且不在 History 里的条目，
  再调 8002 会返回 `协议错误 8000: roleId has no completed missions`。
  所以判定交给服务端：按 1/2/3 各扫一次，8000 当作「无可领取」而非失败。
- 顺带：8000 错误同时说明——**任务奖励不会重复发放**，可以放心每天全量调用。

### ⚠️ 8000 曾把整个会话搞挂（2026-10-21 修复）
`ba_session.Session.call` 原来在 **任何协议错误** 时都不推进 `rid` / `N`，直接抛异常。
结果：`multiplereward` 报一次 8000 后，后续所有请求复用同一个 REQUEST-ID，
服务端一直重放那条错误响应 —— 表现为**所有接口 500**（当时 mail/shop/arena 全挂）。
修法：错误响应同样颁发下一个 rid，非 33004 的错误照常推进再抛。
验证：故意触发 8000 → 会话继续可用（rid/N 正常递增），四个模块接口全部 200。

## 3. 商店（11 个分类）

客户端一次拉全部商店，`CategoryList` 固定：

```json
{"CategoryList": [0, 36, 37, 1, 21, 2, 33, 10, 25, 26, 20]}
```

实测返回 **11 个 `ShopInfos`**，页签名直接对齐游戏内文案（取自 `LocalizeDBSchema` 原文）：

| Category | 游戏内页签 | 商品数 |
|---|---|---|
| 0 | 常规道具 | 24 |
| 36 | 青辉石·每日商品 | 84 |
| 37 | 青辉石·每周商品 | 92 |
| 1 | 神名精髓I | 0（Eligma 独立接口，见 §6） |
| 21 | 神名精髓II | 16 |
| 2 | 总力战 | 175 |
| 33 | 大决战 | 169 |
| 10 | 战术对抗赛 | 16 |
| 25 | 综合战术测试 | 50 |
| 26 | 悬赏通缉 | 24 |
| 20 | 熟练证书 | 62 |

> 命名口径：一律用游戏内文案——`战术对抗赛`（不是竞技场）、`悬赏通缉`（不是悬赏）、
> `综合战术测试`（不是演习）、`神名精髓I/II`（ASCII 的 I/II，不是罗马数字 Ⅰ/Ⅱ）。

**⚠️ ShopExcel 与 ShopRefreshExcel 的 Id 会撞车（关键坑）**：
20000 段两边都有，含义完全不同 —— `ShopExcel[20000]` 是神名文字，`ShopRefreshExcel[20000]` 是青辉石每日的制造材料。
选表规则：**商店 `IsRefresh=true` 查 ShopRefreshExcel（购买请求 `IsRefreshGoods=true`），否则查 ShopExcel**。
2026-10-21 实测购买请求 `{"ShopUniqueId":20003,"GoodsId":160003,"IsRefreshGoods":true}` 确认了这条。

**购买**：`shop/buymerchandise(10000)`

```json
{"ShopUniqueId": 8001055, "GoodsId": 80058, "PurchaseCount": 1, "IsRefreshGoods": false}
```
- `ShopUniqueId` = 商品列表里的 `ShopExcelId`（= `ShopExcel.Id`）
- `GoodsId` = `ShopExcel[ShopExcelId].GoodsId[0]`
- 抓包样本买过：熟练证书 ×2、悬赏 ×4、演习 ×1（对应 `PurchaseCount` 2/4/1）

**已知缺口**：本地表没有 `Goods` 数据表，`ShopInfoExcel` 只有支付货币类型没有数量，
`ShopExcel` 也没有价格字段 → **UI 无法显示价格**；部分分类（活动/普通/成长）连 `GoodsId` 都解析不到，
这些行的「买」按钮直接隐藏，避免发出无效请求。

## 4. WebUI 现状

- 三个卡片：邮箱（一键领取）、任务奖励（按类别扫）、商店（分类下拉 + 手动买 1）

## 5. 商品名称与图标（2026-10-21 接入）

**名称/描述**：`scripts/gen_goods_info.py` 读 `tables/ExcelDB.db` 的 `GoodsDBSchema`（9379 条 flatbuffer，
里面明文内嵌 Unity 资源路径），用**图标路径**做连接键，和 `tables/item_names.json`（1061 条带 name_cn/desc_cn/rarity/icon）
对上，产出 `tables/goods_info.json`。不用解 flatbuffer。

**图标**：`scripts/extract_icons.py`（需 UnityPy + Python ≤3.12）从模拟器的
`files/AssetBundles/uis-01_common-02_equipment-*textures*` 与 `uis-01_common-03_nonequipment-*textures*`
导出 Texture2D（这些 bundle 里是 Texture2D 不是 Sprite），存到 `webui/static/icons/`（1340 张 PNG）。
该目录已 gitignore（游戏素材，不进库），换机器用脚本重导即可；`webui/server.py` 用 `/static` 挂载。

**覆盖率**（2026-10-22 更新）：**712/712 全部有中文名**，709/712 有图标。

名称的权威来源是 `tables/full/ExcelDB/LocalizeEtcExcel.json`（5377 条，`Key → NameKr/DescriptionKr`，
国服这个字段里存的就是中文）：拿商店表每行的 `LocalizeEtcId` 去查即可，比按图标反查 `item_names` 完整得多。
`goods_info.json` 现在只用于补图标路径和稀有度。

**家具图标**在另一组 bundle：`uis-01_common-16_cafeitem-_mxload-textures-*`（7.9MB）与
`uis-01_common-16_cafeitem-template-_mxload-textures-*`（10MB），一次导出 **957 个 `My_*` 家具图标**。

> 青辉石·每周的商品来自 `ShopRefreshExcel` 的 GemWeekly 池（263 条，分 90/91/92 三个 refresh group），
> 会**随机轮换**，所以不能只导当前在售的那几个 —— 整组拉全一次到位，之后无论换到哪批都不用重新解包。

最终覆盖率：**712/712 有中文名，712/712 有图标**（`webui/static/icons` 共 2376 张 / 139MB，已 gitignore）。

## 6. 神名精髓（Eligma）商店：独立协议，不在 shop/list 里

2026-10-21 实测购买请求（master 买圣娅（泳装）碎片）：

```
POST /api/shop/buyeligma    Protocol 10004
{"GoodsUniqueId": 20168, "ShopUniqueId": 20168, "CharacterUniqueId": 10085, "PurchaseCount": 1}
```

结论：
- **商品目录不在 `shop/list` 的 `ShopProductList` 里**（Category 1 永远是空数组，客户端自己收到的响应也是空）。
  服务端只在 `shop/list` 返回 `ShopEligmaHistoryDBs`（每个角色已购次数，实测 41 条），
  商品列表是客户端用「角色名册 + 精髓价格/限购规则」自己拼出来的。
- 购买走独立协议 `shop/buyeligma(10004)`：`GoodsUniqueId = ShopUniqueId = 20xxx`，另有 `CharacterUniqueId`。
- **两个页签的分工**：Ⅰ = 学生碎片（Eligma Ⅰ），Ⅱ = 成长材料（Eligma Ⅱ，Category 21，
  下次刷新 2026-11-01，约四周一轮）。
- **价格规则（社区三处一致 + 数据自洽）**：1 精髓/片起步，**每买 20 片涨 1，5 封顶**；
  只能买已拥有角色的碎片。（台服 wiki 常见问题 / 巴哈兑换机制帖 / namu wiki 同口径）
  实测校验：已购 75 片 → 4 精髓；36 片 → 2；13 片 → 1；1 片（master 买的那次）→ 1。
- WebUI 已接只读视图 `GET /api/shop/eligma`：按名册 + `ShopEligmaHistoryDBs` 算出
  每个学生「已购片数 / 当前单价 / 距涨价还差几片」，选到「神名精髓I」分类时展示。
  碎片图标走「学生名 → item_names 里『XX的神名文字』的 icon」映射，174/174 全命中。
  购买仍未开放（要走 `shop/buyeligma`，且限购上限与星级/专武相关，还没吃透）。

顺带确认了另一个坑：`ShopExcel` 与 `ShopRefreshExcel` 的 Id 段重叠（20000 起），
必须按商店 `IsRefresh` 选表，否则青辉石每日的制造材料会被认成神名文字。


## 7. 商店自动购买（2026-10-22 接入）

**配置**（存在 `webui/ui_state.json` 的 `shopAutobuy`）：
```json
{"enabled": true,
 "items": [{"shopExcelId": 3015, "category": 10, "perRound": 1, "rounds": 3}],
 "progress": {"3015": 1}, "lastRun": "2026-10-22"}
```

**「轮」= 刷新轮**：每轮把「还没跑完轮数」的商品各买一次 → 刷新商店 → 进入下一轮。
所以 `30体×3轮 + 60体×2轮` 的实际顺序是：第 1 轮 30+60 → 刷新 → 第 2 轮 30+60 → 刷新 → 第 3 轮只买 30，
不会出现「先把 30 体买 3 轮再回头买 60 体」。单次最多刷新 **3 轮**（游戏每日手动刷新上限）。

**刷新协议**：`shop/refresh(10003) {ShopCategoryType: <category>}`。

> 踩坑：`shop/buyrefreshmerchandise(10007)` **不会真正刷新商店**（只回一份商品列表、PurchaseCount 还全变 1），
> 一开始用它测常规道具，master 反馈"压根没触发刷新"。10003 才是对的。
> 实测（2026-10-22，战术对抗赛）：30体×2轮 + 60体×2轮 → 买到 4 件共 180 行动点、
> 刷新 1 次、商店 `ManualRefreshCount` 变 1。

**保护**：神名精髓I/II（1、21）与青辉石每日/每周（36、37）不参与自动购买，后端直接过滤。

**只有常规道具(0)与战术对抗赛(10)能手动刷新**（每日 3 次上限 → 最多 4 轮 = 首轮 + 3 次刷新）；
其余商店轮数强制 1。

**各商店的自动刷新周期**（由响应里的 `NextAutoRefreshDate` 推算，`shop_state` 已返回 `period` 字段）：

| 商店 | 周期 |
|---|---|
| 常规道具(0)、青辉石·每日(36)、战术对抗赛(10) | 每日 04:00 |
| 青辉石·每周(37) | 每周（周一 04:00） |
| 总力战(2)、大决战(33)、熟练证书(20)、综合战术测试(25)、悬赏通缉(26)、神名精髓II(21) | **每月 1 日 04:00** |
| 神名精髓I(1) | 不自动刷新（独立接口） |

**不跨天保存进度**：商店每天自动刷新，昨天的轮数没有意义；每次执行都从第 1 轮开始。
只保留一个 `lastRun` 日期标记，避免同一天重复执行时白花刷新货币（`force=true` 可强制再跑）。

**执行时机**：一键清日常的「商店」步骤；也可在商店卡片点「立即执行」。

**已知待验证**：刷新路径尚未实弹（要花 10 币 / 40 钻），单轮购买已实测通过。
