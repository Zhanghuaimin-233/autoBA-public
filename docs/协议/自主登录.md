# 自主登录

> **状态**：已实现 ｜ **日期**：2026-10-16
> **目标**：不依赖游戏抓包，手机号+验证码自主获取 yostar Token → BA account/auth → MxToken → 全自动会话。
> **进展**：协议链全通（签名 oracle / 自主 quick-login 实弹 200 / send-sms+login 请求体实锤）。滑块触发条件待实测。

## 0. 链路总览

```
手机号+验证码 ──> sdk-api.yostar.cn (user/send-sms, user/login) ──> yostar Token（长效）
yostar Token ──> gsqc-api (account/auth, 新 key 重加密防缓存) ──> MxToken
MxToken ──> ba_session（rid 链 + N 计数）──> 全部业务接口
```

## 1. yostar sdk-api（AiriSDK 1.16.1）

### 1.1 鉴权头 Authorization（全部请求）

```json
{"Head": {<Head 对象>}, "Sign": "<base64 签名>"}
```

Head（LinkedHashMap 保序，Gson 紧凑序列化）：

| 字段 | 值（实测样本） |
|---|---|
| PID | `CN-BA` |
| Channel | `official` |
| Platform | `android` |
| Lang | `zh` |
| DeviceID | 设备指纹（如 `deadbeefdeadbeef`） |
| Version | `1.16.1` |
| GVersionNo | `73` |
| GBuildNo | 空串 |
| DeviceModel | 如 `Xiaomi 00000XXX`（占位） |
| RID | 每请求随机 uuid4 |
| UID / Token | 登录后携带（未登录省略） |
| Time | unix 秒 |

**Sign = AiriSgClient.sign((headJson + bodyJson).getBytes(), 0)**——Head JSON 与请求体 JSON **直接拼接**后签名。签名确定性（同输入同输出，172 base64 字符 = 128 字节 = RSA-1024 形态）。算法在 `libairisgcore.so`（native，RegisterNatives 注册，OpenSSL 静态链接）。

**签名实现（2026-10-27 更新）：纯 Python 复现**——`sign_offline.py` 默认调用 `reverse/sign_pure.py`（SHA-256 + RSA-1024 PKCS#1 v1.5），无需 Java、unidbg 或 `libairisgcore.so`；算法与两把客户端内置私钥的还原过程见 `reverse/README.md`。
- 原 unidbg 模拟路径保留为 `offline_sign_unidbg()`，仅作回退。
- 历史路线均未成功：模拟器 Java 桥不可用、arm 模块枚举不可见、内存中未找到 DER 私钥、BIGNUM 扫描候选均非 n 因子。

### 1.2 接口（SdkConst$Uri 全清单节选）

| 接口 | 请求体 | 说明 |
|---|---|---|
| `user/send-sms` | `{"Captcha":{"Randstr":"","Ticket":""},"PhoneNumber":"13...","Scene":"login"}` | 发验证码；滑块通过后填 Randstr/Ticket |
| `user/login` | `{"OpenID":"手机号","Secret":"","Token":"验证码","Type":"mobile","UserName":""}` | 验证码登录；响应 `Data.User.Token` |
| `user/quick-login` | `{}` | 静默续期（UID+Token 校验） |
| `user/check-captcha` | — | 滑块校验 |
| `user/detail` | — | 账户详情 |

注意 yostar 字段名复用：login 的 `OpenID` 装手机号、`Token` 装短信验证码。

### 1.3 滑块（腾讯天御 TCaptcha）

- 2026-10-16 实测：游戏登录界面发码触发滑块（H5），通过后 ticket/randstr 填入 Captcha。
- **触发条件未知**（新设备？频次？）——自主链 Captcha 空串发送待实测；DeviceID/设备指纹与历史一致时可能低危免滑块。
- 自主链遇滑块时的降级：游戏里人工过一次滑块（ticket 可跨请求复用与否待验证）。

### 1.4 Token 特性（实测）

- **长效**：测试 token 从 10-11 起跨 5 天一直有效（quick-login 续期）。
- **重新登录不变**：手机号+验证码重新登录后 `User.Token` 仍是原值（绑定账号+设备指纹）。
- 登录响应同时给：User{ID, Token}、Identity（实名打码）、Keys（NickNameEnc=AES 加密手机号，key/iv 同 getAAesKey/Iv）。

## 2. AES 材料（getAAesKey/getAAesIv）

- SDK 下发固定 32B AES-256 key 与 16B iv（具体值不随公开仓提供）
- 用途：AES/CBC/PKCS5Padding——NickNameEnc 解密、部分请求字段加密（AESUtils.decrypt 输入为 hex）

## 3. BA account/auth（yostar Token → MxToken）

见 `ba_session.py`。要点：

- 请求体 16 字段（DevId/DeviceUniqueId/DeviceModel/Token/SdkPid=CN-BA/ResUrl 等），从历史抓包模板取。
- **必须新随机 key 重加密**（字节级相同命中去重缓存，返回缓存响应不建会话）。
- 资源版本头过旧报 90007 并告知最低版本（动态升级）。
- auth 响应：SessionKey{AccountServerId, MxToken} + **requestid（rid 链起点）**。

## 4. ba_session 会话机制（rid 链 + N 计数）

- **每个响应颁发下一个请求的 REQUEST-ID**；复用旧 rid = Resendable 幂等缓存（返回上次响应、静默不执行）；陌生 uuid = 33004。
- Hash = (Protocol << 32) | N；auth 的 N 为会话起点，逐请求 +1；N 错也报 33004。
- 会话可落盘续用（`ba_session.py` / session_state.json）。
