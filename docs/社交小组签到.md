# 社交小组（社团）签到 — 2026-10-17 抓包定案

> 数据源：10-11 ~ 10-14 抓包（`/api/clan/lobby` ×3、`/api/clan/check` ×59、`/api/clan/chat/records` ×5）+ 游戏表 `MissionExcel` / `CurrencyExcel`。
> 结论：**没有独立的签到接口，进入社团大厅就是签到。**

## 1. 接口清单

| 接口 | Protocol | 作用 | 请求字段 | 样本 |
|---|---|---|---|---|
| `/api/clan/lobby` | 28000 | **进入社团大厅 = 当日签到**，返回社团与成员状态 | 无 | 3 |
| `/api/clan/check` | 28019 | 状态轮询（红点/新消息检查），**空响应，不签到** | 无 | 59 |
| `/api/clan/chat/records` | 90009 | 社团聊天记录 | `ClanDBId`、`LastChatId` | 5 |

`check` 调用频率很高（每天十几次），响应除了标准头之外没有任何业务字段，是客户端轮询；不要拿它当签到。

## 2. 签到证据

- `lobby` 每天只调一次，时间点与签到吻合：

  | 时间 | AttendanceCount |
  |---|---|
  | 10-11 18:29:53 | 421 |
  | 10-12 20:52:59 | 422 |
  | 10-13 18:18:16 | 423 |

- 10-12 那次 `lobby` 响应里多出 `MissionProgressDBs`，其中 mission **1603** `Complete: true`，`StartDate` 正好是当天。
- `MissionExcel` 1603 定义：
  - `Category: DailySudden`，`ResetType: Daily`
  - `CompleteConditionType: **Reset_ClanLogin**`，`CompleteConditionCount: 1`
  - 奖励：`Currency` 18 × **20**
  - Currency 18 = **熟练证书**（MasterCoin）

即：每天第一次进入社团大厅 → 出勤 +1、完成「社团登录」日常任务、给 20 熟练证书。

## 3. 请求 / 响应

请求（无业务字段，标准头即可）：

```json
{"Protocol": 28000, "Resendable": true, "Hash": ..., "IsTest": false,
 "SessionKey": {...}, "AccountId": ..., "OSType": 2}
```

响应：

```
AccountClanDB          {ClanDBId, ClanName, ClanChannelName, ClanNotice,
                        ClanMemberCount, ClanManagerCount, ClanJoinOption,
                        ClanPresidentNickName, ClanPresidentRepresentCharacterUniqueId, ...}
AccountClanMemberDB    {AccountId, AccountLevel, AccountNickName,
                        RepresentCharacterUniqueId, ClanDBId,
                        AttendanceCount, ClanSocialGrade,
                        JoinDate, LastLoginDate, GameLoginDate, AppliedDate,
                        AttachmentDB: {EmblemUniqueId}}
ClanMemberDBs          [同上成员结构 + AccountNickName]（50 人）
DefaultExposedClanDBs  []
MissionProgressDBs     [仅在签到任务完成时出现]
```

`AccountClanMemberDB` 里**没有** `LastAttendanceDate` 字段，只有累计 `AttendanceCount`——判断今天签没签到只能靠任务 1603 的状态或对比计数。

## 4. 自动化要点

1. 每天调用一次 `/api/clan/lobby` 即可完成签到（建议当天首次运行时做，4:00 刷新后）。
2. 重复调用是否幂等未实测；按 `Reset_ClanLogin` 语义应该只记一次，但 `AttendanceCount` 是否会重复 +1 需要一天内调两次验证。
3. 签到奖励走任务系统（mission 1603）。抓包里**没有**对 1603 的 `/api/mission/reward` 调用，奖励可能是自动发放或需在任务界面领取——待实测。
4. `clan/check` 可以安全调用（纯轮询、空响应），但没必要。

## 5. 实弹验证（2026-10-17 23:05）

- 调用 `lobby` 返回 `AttendanceCount=427`、`LastLoginDate=2026-10-17T22:57:35`——当天 22:57 已由游戏端签到。
- 再次调用 `lobby`（WebUI 的签到按钮）：出勤仍为 427，`LastLoginDate` 也没变 → **同一天重复进入是幂等的**。
- 结论：`LastLoginDate` 是当日首次进入的时间戳，可直接用来判断「今日已签到」（按 4:00 游戏日切分）。
- 已签到时响应里不会再带 mission 1603（任务完成记录只在完成那次出现），所以任务状态不能作为签到判据。

## 6. WebUI 接入

- `GET /api/clan/state`：读大厅（同时完成签到），返回社团/成员/出勤/今日签到状态，带 60s 缓存。
- `POST /api/clan/checkin`：强制重读（跳过缓存），用于「签到」按钮。
- 「社交小组 · 签到」卡片：标题栏显示社团名 + 出勤天数 + 今日状态，正文展示社团人数、会长、昵称、社交等级、加入/最近登录、公告；一级折叠与其它卡片一致。
- 出勤变化记录在 `clan_state.json`（运行态，已 gitignore），用于计算本次是否 +1。
