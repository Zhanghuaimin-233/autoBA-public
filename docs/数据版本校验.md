# 数据版本校验（新内容 / 新关卡预警）— 2026-10-17

> 目的：客户端/tables 没更新时，游戏若开放了新关卡，一键日常不能傻刷旧关。需要提前报警。

## 1. 为什么不能靠关卡列表

- 悬赏通缉的关卡目录在**客户端表** `WeekDungeonExcel` 里，服务器没有"给我全部关卡"的接口。
- `weekdungeon/list` 只返回**已通关**记录（`WeekDungeonStageHistoryDBList`）和 `AdditionalStageIdList`（目前恒空）。
- 新关卡在通关之前不会出现在任何响应里。

## 2. 可行信号：auth 的 90007

客户端每次登录会带 `RESOURCE-VER` / `TABLE-VER`。版本低于服务器最低要求时，auth 直接返回：

```
ErrorCode: 90007
Reason: resource version is too low, v=202001010000 lowest=202610131404
```

**探测方法**：故意用极低版本（`202001010000`）发一次 auth，读 `lowest=`。这次请求不会建立会话，也不消耗任何东西。

实测（2026-10-17 23:20）：`lowest=202610131404`，与本地表版本一致。

## 3. 本地表版本

`tables/table_version.json`：记录 `tables/full/ExcelDB` 对应的客户端数据版本（当前 `202610131404`，10-13 dump）。

- `server > local` → 游戏数据已更新（可能新增关卡）
- `server == local` → 表是最新的

## 4. 接口

| 接口 | 说明 |
|---|---|
| `GET /api/resource/status?force=1` | 探测并比对；默认缓存 1 小时 |
| `POST /api/resource/ack` | `{"version": "..."}`，记录"知道了"，同版本不再提醒 |

返回：`{local, server, outdated, ack, checkedAt, error}`

运行态：`resource_state.json`（已 gitignore）。

## 5. 界面

顶部黄色提醒条：

> 游戏数据已更新：本地表 202610131404 → 服务器 202611xxxx。可能新增关卡/内容，建议先更新 tables 再刷票。 [知道了]

点"知道了"写入 ack，直到下一次版本变化才再出现。

## 6. 局限与兜底

- **版本变化 = 客户端数据更新**，可能是新活动/新角色，不一定是新关卡。但它是目前最早的可靠信号，宁可多提醒一次。
- **精确确认**：`weekdungeon/list` 的 history 里出现表外 StageId（例如 30111），就说明确实开了新关，而且你已经通关。
- **未做**：拿到 ExcelDB 资源 CDN 地址后，可以在版本变化时自动下载新表，直接 diff `WeekDungeonExcel` 得到"新增了哪几关"。目前需要手动更新 tables。
