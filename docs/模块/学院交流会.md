# 学院交流会

> **状态**：已实现 ｜ **日期**：2026-10-18

## 1. 基础数据

| 项 | 值 |
|---|---|
| 列表接口 | `/api/schooldungeon/list`（38000，无请求字段） |
| 扫荡接口 | 与悬赏通缉共用 `/api/contentsweep/request`（27000） |
| 扫荡请求 | `{"Content": 8, "StageId": 60104, "Count": 6, "EventContentId": 0}` |
| 票 | `Currency 23 = SchoolDungeonTotalTicket`（学院交流会挑战券），每日补 6 张（共享池） |
| 关卡表 | `SchoolDungeonStageExcel`：SchoolA/B/C 各 4 关（A–D），当前最高 D |

三张图（`DungeonType` → 游戏内名，LocalizeExcel 原文）：

| DungeonType | 游戏内名 | 掉落系列 |
|---|---|---|
| SchoolA | 学院交流会 - 崔尼蒂 | 弹簧 |
| SchoolB | 学院交流会 - 歌赫娜 | 击锤 |
| SchoolC | 学院交流会 - 千禧年 | 枪管 |

> 映射**实锤**：`FarmingDungeonLocationManageExcel` 直接给出 `SchoolA→崔尼蒂、SchoolB→歌赫娜、SchoolC→千禧年`（Order 1/2/3），不是推断。

## 2. 与悬赏通缉的差异

1. **扫荡 Content=8**（悬赏是 3）。
2. **每关额外消耗行动点**：A 10、B–D 15（`StageEnterCostId: [23, 5]`）。本工具只标注、不校验体力。
3. 三星记录字段是 **`StarFlags`**（布尔数组），不是 `StarGoalRecord`——两种格式都做了兼容。
4. 券是共享池（Currency 23），每日 6 张；同样没有只读余额接口。

「最新关」判定与悬赏完全一致：已开放最高关（表内最大 StageId）vs 三星可扫最高关（`/api/schooldungeon/list` 的历史记录），不一致默认停；数据版本落后默认锁。

## 3. 接口

| 接口 | 说明 |
|---|---|
| `GET /api/scrimmage/state` | 三图状态 + 版本状态 + 体力标注 |
| `POST /api/scrimmage/sweep` | `{"counts": {...}, "force": false}`，校验合计 ≤ **当前余额**（CurrencyDict["23"]，同悬赏） |

## 4. 验证边界

- 状态/分配/确认条实跑通过（确认条会显示预计消耗体力，如 2+2+2=90 AP）
- **未执行真实扫荡**；票与体力未消耗
- 扫荡响应的奖励名映射可能不全（`item_names` 缺失部分专属武器素材 ID），日志里会显示 `Item xx`——不影响扫荡本身
